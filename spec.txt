FocusFlow
AI-Powered Productivity & Study AssistantComplete Production Android App Specification & Agent Build Brief
Purpose: Build a polished, publishable Android application in Kotlin that demonstrates modern Android engineering, AI integration, offline-first architecture, cloud synchronization, background processing, analytics, testing, and production release practices.
1. Product Overview
FocusFlow is an AI-powered productivity and study-management application for students and professionals. It helps users create tasks and goals, break complex work into actionable steps, generate adaptive study/productivity plans, track habits, run focus sessions, receive intelligent reminders, analyze productivity, work offline, and synchronize data across devices.
2. Primary Product Goals
Feel like a real commercial Android product rather than a university/demo CRUD application.
Use Kotlin and Jetpack Compose throughout the native Android application.
Demonstrate production-grade architecture and state management.
Combine Android engineering with AI and data-driven productivity insights.
Work reliably offline and synchronize changes when connectivity returns.
Be suitable for Google Play publication and professional portfolio/GitHub presentation.

5. Visual Design System
The supplied reference images are the primary visual direction. Match their visual language as closely as possible: premium, modern, minimal, clean, spacious, rounded cards, strong typography hierarchy, subtle elevation, sophisticated dark/light themes, smooth animations, and consistent iconography.
Create reusable color, typography, spacing, radius, button, card, input, bottom-sheet, and navigation tokens.
Spacing scale: 4 / 8 / 12 / 16 / 24 / 32dp.
Corner radius scale: 12 / 16 / 20 / 24dp.
Use meaningful animations for navigation, task completion, progress, AI generation, bottom sheets, dialogs, charts, and the focus timer.
Avoid excessive gradients, random colors, clutter, default-looking templates, unnecessary borders, and emoji-driven UI.
If exact reference screenshots are supplied to the agent, treat them as pixel-level visual targets rather than generic inspiration.

11. AI Task Breakdown
Allow the user to enter a large goal such as “I need to build a machine learning project.” The AI should return structured, actionable tasks with descriptions, estimated minutes, and priority.
Use structured JSON responses rather than parsing arbitrary natural-language UI output.
Allow users to add all generated tasks, edit them, remove them, or regenerate the plan.
12. AI Study/Productivity Planner
Inputs: goal, deadline, available hours, current skill level, preferred study time, and existing commitments.
Generate daily tasks, study sessions, breaks, revision sessions, and priority order. If a session is missed, allow the schedule to be regenerated.

Habit fields: name, description, frequency, reminder, goal, and icon.
Support daily, weekly, and custom-day schedules. Track current streak, longest streak, completion rate, and history.
15. Calendar
Provide Day / Week / Month views showing tasks, deadlines, focus sessions, study sessions, and appropriate habit events. Tapping an event opens details.
16. Analytics
Display total focus time, tasks completed, completion rate, current streak, and longest streak.
Charts: daily focus time, weekly productivity, task completion, category distribution, and habit consistency.
Support Week / Month / Year. Use real Room/Firestore data; do not keep fake statistics after actual data exists.
17. AI Productivity Insights
Analyze aggregated productivity history and generate useful insights such as when the user performs best, average focus duration, consistency changes, and scheduling recommendations. Minimize transmission of raw personal data.
18. Offline-First & Sync
Room should be the local source for user-facing data. Tasks, habits, focus sessions, and analytics must remain usable without internet. Synchronize changes with Firestore when connectivity returns and implement reasonable conflict handling.
Conceptual flow: Room → Repository → Sync Manager → Firestore.
19. Firebase & Data Model
Use Firebase Authentication and Cloud Firestore with security rules isolating each user's data.
users/{userId}
tasks/{taskId}
goals/{goalId}
habits/{habitId}
focusSessions/{sessionId}
plannerSessions/{sessionId}
Do not leave Firestore publicly readable/writable.
20. Notifications & Background Work
Support task reminders, deadline warnings, habit reminders, focus-session events, daily plans, and carefully controlled AI recommendations.
Use WorkManager and Android notification APIs appropriately. Respect Android notification permissions and do not spam users.

22. Error, Loading & Empty States
Every major network/API operation must expose Loading, Success, Error, and Empty states.
Handle no internet, Firebase errors, AI errors, invalid input, authentication failures, database failures, and timeouts without crashing.
Use polished skeleton/loading states rather than blank screens.
Examples: “Nothing planned yet.”, “Build your first habit.”, “Your focus history will appear here.”
23. Security
Never hardcode production AI API keys in the APK.
Use a secure backend for secret AI credentials.
Use HTTPS.
Use Firebase security rules.
Validate inputs.
Do not log passwords, tokens, API keys, or private user data.
24. Testing
Unit-test task calculations, habit streaks, productivity calculations, planner logic, repository behavior, and AI response parsing.
UI-test login, task creation/completion, focus session, and navigation.
Test offline functionality and synchronization.
25. Performance & Accessibility
Optimize Lazy lists, database queries, Compose recomposition, images, and network calls.
Avoid unnecessary recompositions and load only required Firestore data.
Provide content descriptions, adequate touch targets, dynamic text support, screen-reader support, and good contrast.
Do not rely only on color to communicate state.
